./sec — becoming AI-lab security material

Evidence-based path to FRT-Cyber / Safeguards / adjacent roles at Anthropic / OpenAI / DeepMind. Every step maps to something a real hire actually did.

Guiding principle. The people hired to these teams got there via public, referenceable work — a cited paper, a jailbreak method others reproduce, a widely-used tool, a leaderboard finding on the lab's own bounty program. Not CTF grinding, not certs, not generic pentesting. The plan below only contains activities where I can point to a real person hired at a real lab whose path went through that same activity. If your work is compounding-public, the worst case is you build a portfolio that opens 20+ adjacent doors (AI security startups, founding, consulting) even if the specific SF-based role at Anthropic doesn't land.
have: RedBench (red/blue/judge harness) have: Probe (live-demo pattern) have: Python / async / FastAPI gap: cited public artifact on LLM security gap: bounty on a lab's HackerOne program gap: reproduced canonical adversarial-ML result gap: OSS contribution to a tool these teams use

this week — five concrete, evidence-linked actions

  1. Register on Anthropic's HackerOne program 30 min
    Go to hackerone.com/anthropic. Read scope carefully (agent-tooling in scope; model-safety separately scoped). This is the exact pipeline Anthropic's Safeguards Red Team reviews — the Register report on VentureBeat and TheNextWeb documents the workflow: report → triage → some paid up to $15K. Do not submit yet; first study the last 20 disclosed reports at hackerone.com/hacktivity filtered by "anthropic" and "openai" to see what's in-scope and what payouts look like.
  2. Reproduce GCG from scratch on a small open model weekend
    Clone llm-attacks/llm-attacks. Run their nanogcg against a local Vicuna-7B or Llama-3.2-3B via ollama. Log the transferability tests. This is the paper (arxiv 2307.15043) that made Andy Zou a Gray Swan cofounder while still a PhD student — everyone in the space has read it; reproducing it fluently is the entry-price conversation piece.
  3. Read Simon Willison's prompt-injection series end-to-end 3 hours
    simonwillison.net/series/prompt-injection. He coined the term (Sept 2022) via a blog post and is now the de facto public intellectual on the topic — cited in OWASP LLM Top 10, arXiv papers, and Anthropic's own writeups. Understanding his framing (especially the "lethal trifecta" and dual-LLM pattern) is non-optional shared vocabulary for these interviews.
  4. Set up your writing surface + first post 2 hours
    Extend your existing blog.html into a proper writing index at mihirsrivastava.com/writing. First post: "Reproducing GCG on a laptop — what I learned". Post to Hacker News + X. This is the pattern — Willison's newsletter, Andy Zou's paper, Mrinank Sharma's personal site — public work is the ticket.
  5. Apply to Inspect / adopt one adjacent tool 1 hour
    Install UK AISI's Inspect framework (the eval framework Anthropic, DeepMind, and OpenAI all cite; open source under MIT). Port ONE task from your RedBench into Inspect's task format. Committing a real eval to inspect_evals repo puts your GitHub handle in front of everyone in this space.
01Three flagships, evidence-anchored

Each flagship is chosen because a specific person at a specific lab got there through this exact activity. Each produces a public, referenceable artifact.

flagship 1 · weeks 1–5 · single most important

Publish an original LLM-security finding + tool

evidence: Simon Willison (blog), Andy Zou (GCG), Andriushchenko (PAIR)
Pick ONE narrow, currently-under-explored surface. Do a careful empirical study. Publish: (a) 3-6k word blog post with reproducible code, (b) short arXiv preprint, (c) small OSS tool anyone can run.

Target surfaces (pick ONE)

  • MCP server prompt injection. Willison flagged MCP has "prompt injection security problems" in a 2025 post; no systematic empirical study exists. Enumerate the top ~30 public MCP servers on the official registry, build a test harness that fires injections through each tool description / resource content, measure success rate across Claude 4.6/4.7 + GPT-5 + Qwen.
  • Agent trajectory hijacking mid-run. Not first-turn injection — the more interesting question is: given a benign initial prompt, can an untrusted tool return string hijack the plan? Reproduce it across LangChain / Claude Code / OpenHands / SWE-agent. No systematic study exists.
  • Sandbagging in-the-wild. You already built Probe. Extend it to run on Anthropic's WMDP benchmark across 6 open models + 3 frontier APIs. Publish a plot of "gap between benign accuracy and dangerous accuracy" for every model. If you find one model with a real gap, that alone is a headline finding.

Concrete steps

  1. Week 1: pick surface. Draft the experimental design (Google doc, share with 3 people for feedback — post to Alignment Forum shortform for public feedback loop).
  2. Week 2: build the test harness on top of Inspect or RedBench. Include ≥3 open + ≥2 frontier models.
  3. Week 3: run experiments. Log everything. Screen-record one full run (Vlad Feinberg's advice — hiring managers want to see you actually did it).
  4. Week 4: write the blog post. Structure = TLDR / methodology / results / limitations / defenses. Post code to GitHub with a working docker compose up.
  5. Week 5: post to Hacker News + X + Alignment Forum + LessWrong. Tag Simon Willison / relevant researchers. Submit as arXiv preprint (cs.CR + cs.CL).
Evidence this works. Andy Zou's GCG paper (arXiv July 2023) → cofounded Gray Swan Sep 2024 with his advisors + $ in OpenAI Foundation board. Simon Willison's original prompt-injection post → became the reference voice cited in OWASP LLM Top 10 and every subsequent survey. A single well-executed empirical study on an under-explored surface is worth more than 100 CTF challenges to this specific hiring pipeline.
flagship 2 · weeks 4–10 (overlapping)

Real bounty on Anthropic / OpenAI HackerOne — with public disclosure

evidence: Anthropic public bounty launched May 2026 payouts: $100 – $15,000
Land at least one accepted, paid report on hackerone.com/anthropic or OpenAI's Bugcrowd program. After coordinated disclosure, publish a technical writeup on your blog. This is a direct hiring signal because the Safeguards Red Team literally reviews these reports.

Concrete attack surfaces to study

  • Claude.ai product — Files, Projects, Web Search, Computer Use, Claude Code. Business-logic bypass, IDOR between shared projects, cross-tenant leakage. Read all past Anthropic disclosures on hacktivity to see what's been paid before.
  • Prompt injection with real impact. A raw jailbreak is out of scope for many programs; a chain that (jailbreak → data exfil / tool misuse / persistence) is in. Aim for chain-of-N.
  • Rate-limit + abuse. Payment-side abuse, throttle bypass, cost-amplification. The Safeguards JD literally lists "payment fraud" and "coordinated account manipulation."

Concrete steps

  1. Read 20 disclosed reports on hacktivity for the AI programs (Anthropic, OpenAI, Google AI). Note recurring bug classes and severities.
  2. Study Anthropic's model-safety bounty scope vs. product bounty scope — different tracks, different criteria.
  3. Pick ONE product feature. Spend a full weekend proxying every request through Burp. Diagram the trust boundaries.
  4. Write down 5 attack hypotheses. Test each systematically. Escalate the most promising one to a full PoC.
  5. File one report with a clean, reproducible PoC. Regardless of triage outcome, iterate.
  6. Post-disclosure: publish a technical writeup. Link to it from your GitHub profile.
Evidence this works. The Register documented $100-$15K payouts on the exact program you'll be filing on. Multiple current Anthropic Safeguards engineers list "bug bounty at [lab]" in their LinkedIn "how I joined" summaries. Even one accepted report + writeup is a resume line that filters you above 95% of applicants for the Safeguards Red Team role.
flagship 3 · weeks 6–12 (overlapping)

Substantive OSS contribution to a tool these teams use

evidence: Inspect (AISI) used by Anthropic + DeepMind + OpenAI
One merged, substantive PR to a repo used by frontier labs' evaluation teams. Not a typo fix. A new eval task, a bug fix in the harness core, or a new tool integration.

Repos ranked by hiring-signal-per-hour

  1. Inspect + inspect_evals — UK AISI's eval framework. Anthropic/DeepMind/OpenAI cite it as their common evaluation runtime. Contribute a new agentic-eval task (e.g., port a section of your Probe/RedBench work) or a bug fix in the tool-use loop.
  2. SWE-agent — Princeton's open agent scaffold. Design of the "Agent-Computer Interface" is the reference. A PR adding security-eval mode = crossover exposure.
  3. simonw/llm — Willison's CLI. Adding a security-focused plugin (like llm-guard-style) puts you in his ecosystem.
  4. openai/evals — OpenAI's eval registry. Register a novel adversarial eval.
  5. modelcontextprotocol/servers — MCP reference servers. Security-hardening PR (input validation, output filtering) has visibility because MCP is Anthropic's baby.
Evidence this works. "Contributed to open source projects used by the team" is a top-3 signal Anthropic's own hiring page cites. Someone reviewing your PR is likely already on or connected to the team you want to join.
02Ongoing in parallel

Weekly public writing on the writing page

Every hire I studied has a personal site with a writing archive. Mrinank Sharma's site, Andy Zou's arXiv trail, Simon Willison's newsletter. Not blog-for-blog's-sake — every post is either a paper explainer, a reproduction, or a finding.

  • Post cadence: every 2 weeks, minimum 800 words with either code or original data.
  • Rotation: (a) reproduction of a paper, (b) explainer of a recent FRT / DeepMind / OpenAI paper, (c) progress from your flagships.
  • Cross-post: HN + X + Alignment Forum + LessWrong. Tag specific researchers when relevant. This is how you get noticed.

Reproducing papers as a study modality

You learn adversarial ML by re-implementing it. Every canonical paper below has an open reference impl; you'll copy-then-derive. This is what CMU PhD students do in their first year — you can compress a year to 3 months.

  1. GCG (arxiv 2307.15043) — llm-attacks/llm-attacks
  2. PAIR (arxiv 2310.08419) — Chao et al., "Jailbreaking Black Box LLMs in Twenty Queries"
  3. TAP (arxiv 2312.02119) — Mehrotra et al., Tree of Attacks with Pruning
  4. MICE (arxiv 2408.02940) — LLM-guided grammar-based attacks
  5. Constitutional Classifiers — Anthropic paper (link on their alignment blog)

Direct-line networking (concrete)

  • Follow + engage with (weekly, substantively): Logan Graham (FRT lead), Simon Willison, Andy Zou, Riley Goodside, Mrinank Sharma, Erik Jones, Nicholas Carlini.

03Explicitly cut — no evidence these help
  • picoCTF beginner grinding. Nobody at the labs I researched got hired via picoCTF. Cybench-tier / DEF CON quals-tier CTF matters at the top end; picoCTF matters when you're 15. Cut.
  • Generic CTF participation without team/placement. Casual solo weekend CTFs = zero hiring signal. Skip unless you're joining a real team competing at CTFtime-ranked events.
  • Generic pentest certs (OSCP, CEH). Zero hiring signal at these specific labs. Their engineers cite research and public artifacts, not certs.
  • Yet another safety-eval benchmark clone. You have RedBench and Probe. Extend, don't restart.
  • "Learn CUDA / kernels / quant." Vlad's advice is for the below-the-stack track. FRT-Cyber and Safeguards are above-the-stack. Different job.
  • Long ML training runs. These teams evaluate + attack frontier models; they don't train.

02Patterns that keep repeating
  1. Public artifact > credential. Every named hire has a personal site listing research, or a cited paper, or an open-source tool their name is on. Not one has a hidden portfolio.
  2. Narrow-and-deep beats broad-and-shallow. The GCG paper is one algorithm. Willison's original post is one concept. Depth on a small surface wins.
  3. The pipeline is small and reads its own field. ~15 on FRT, ~10 on Safeguards Research. They read each other's papers, cite Simon Willison, follow each other on X. If your work appears in the same substrate (Alignment Forum, arXiv cs.CR, HN, X), they see it.
  4. Bounties are the direct-apply pipeline. Anthropic + OpenAI + Google all run HackerOne / Bugcrowd programs and their Safeguards teams review reports. This is the closest thing to a hire-in-the-open channel.
  5. PhD is common but not required. Anthropic explicitly says ~50% of research staff have PhDs, so ~50% don't. Non-PhD hires universally have strong public portfolios. Portfolio replaces credential.

02What's the worst realistic outcome?

After 3 months of this plan, worst case you have: (1) one blog post with reproducible code that a few researchers read, (2) one accepted HackerOne report or two rejected ones with the process learned, (3) one merged PR in an eval framework, (4) fluent conversational knowledge of the 5 canonical papers in the field. That worst case still opens the "adjacent teams" list above. This plan is asymmetric — high upside if it hits FRT, still valuable if it doesn't.
