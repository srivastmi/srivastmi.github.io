./sec — becoming FRT-Cyber material

A 90-day roadmap to become a strong candidate for Anthropic's Frontier Red Team (Cyber). Not linked anywhere.

Mission. Ship the artifacts, publish the writeups, and log the CTF/CVE trail that turn "curious engineer with a safety-eval side project" into "credible cyber-AI research hire." The plan takes seriously two operating principles: Vlad Feinberg's — work above the LLM stack on rigorous agent experiments and let public GitHub + writeups do the talking; and FRT's — measure frontier capabilities on real cyber targets and translate results into policy-legible demos (see exploit-evals, 0-days, Glasswing).
have: RedBench (red/blue/judge harness) have: Probe (live-demo pattern) have: Python / async / FastAPI gap: offensive security artifacts gap: CVE / bounty track record gap: CTF placements gap: agent-on-target infra

this week (do these five things)

  1. Register on picoCTF, CTFtime, HTB Starting Point. Solve 3 picoCTF challenges — one crypto, one web, one pwn.
  2. Fork RedBench into a new repo ctf-bench. Scaffold a SecurityChallenge participant with a Docker-sandboxed shell/python/curl tool. Point it at a single picoCTF pwn.
  3. Read Cybench (Stanford) end-to-end and skim FRT's exploit-evals to internalize what "good" looks like.
  4. Set up a public technical blog page under mihirsrivastava.com/writing (or use existing blog.html). First post drafts: "Sandbagging as a cyber-adjacent capability."
  5. Publish Probe + RedBench on GitHub with clean READMEs and one demo GIF each. Pin them.
01Flagships

Three shipped artifacts, ordered so each unlocks credibility for the next. Every flagship = public GitHub repo + writeup + one video/GIF demo.

flagship 1 · weeks 1–4

ctf-bench — autonomous CTF agent + eval harness

maps to: FRT sample project #3 reuses: RedBench provider/budget/judge layer artifact: repo + leaderboard + writeup
Open-source agent + benchmark that runs Claude / GPT / Qwen / DeepSeek against picoCTF categories and HTB Starting Point, with deterministic replay, per-challenge cost tracking, and a leaderboard vs. published human solve times. Emits the same JSON envelope RedBench uses so results are diffable across models.
  • Fork RedBench provider layer; add SecurityChallenge participant with ShellTool, PythonTool, CurlTool, GdbTool — each executes in a scratch Docker container.
  • Ingest picoCTF 2019/2023 (~150 challenges, freely licensed). Auto-verify by flag string match.
  • Add HTB Starting Point tier 0/1 (~15 boxes, needs $15 VIP). Verify by hash of user + root flag.
  • Sweep 3 models × 3 prompting strategies (ReAct, plan-then-act, "cyber persona"). Track wall-clock, tokens, cost, turn count.
  • Writeup: "How well do frontier models solve CTFs?" — per-category breakdown + Probe-style live trace viewer.
flagship 2 · weeks 5–8

one CVE / one paid bounty — responsibly disclosed

maps to: "vulnerability research or exploit development" artifact: CVE-YYYY-NNNNN + disclosure writeup
One real vulnerability found and disclosed. Not a lab CTF — a live target. Turns "no offensive experience" into "has done coordinated disclosure." The floor is embarrassingly low; the signal is enormous.
  • Pick ONE bug class for two weeks — recommended: prompt-injection / SSRF / auth-bypass in AI infrastructure (LangChain plugins, vector DBs, MCP servers, agentic frameworks). Plays to your LLM knowledge; underexplored surface.
  • Target 5–10 open-source projects with SECURITY.md or huntr.dev/GitHub Security Lab presence.
  • File one report. Get one CVE assigned. Publish a defensive writeup after patch lands.
  • Bonus: use your own Flagship 1 agent to help find it. That becomes the story for Flagship 3.
flagship 3 · weeks 9–12

purple-arena — live AI-attacker vs. AI-defender demo

maps to: FRT sample projects #2 + #4 reuses: Probe UI, ctf-bench agent artifact: video demo + repo + blog post
A Probe-style live arena: attacker LLM (tools = shell + HTTP) tries to exploit a vulnerable web app; defender LLM (reading structured logs) proposes WAF rules and iptables changes; a judge LLM scores exploitation success and detection latency. Both agents' reasoning visible on screen. Designed to be shareable with non-technical stakeholders — the same demo shape as Anthropic's own writeups.
  • Target: OWASP Juice Shop or a bespoke Flask app with 5 known vulns (SQLi, IDOR, SSRF, RCE, auth bypass).
  • Attacker: ctf-bench agent with tool budget. Defender: log-reading LLM with a small proposal action space.
  • Judge: third LLM emits per-round scoring events. Frontend forks Probe's grid — rows = attack strategies, cols = defense postures.
  • Record a 3-minute OBS video walking through one round. Post to LinkedIn + blog + X.
02Ongoing (all 12 weeks, in parallel)

CTF participation

Real handles beat hand-wavy claims. Interviewers check CTFtime.

  • Solve 2–3 picoCTF challenges per weekend. Track on a public CTFtime profile.
  • Join one weekend CTF per month via CTFtime — even DEF CON quals qualifier tier. Team up (solo is a losing strategy).
  • Keep a public write-ups folder in a repo. This alone is a hiring signal.

Public writing cadence

Vlad's rule: "if you do the work, screen-record and write it up." Hiring managers Google you.

  • One post every 2 weeks under mihirsrivastava.com/writing.
  • Topics rotate: (a) a piece of Flagship progress, (b) a paper explainer, (c) a CTF walkthrough. Never break the cadence.
  • Cross-post to X + LinkedIn with a screenshot/GIF. Tag research handles when relevant.

Landing the outreach

Warm-intro rate on FRT applications approaches 0% without touchpoints.

  • Post a smart question or a small finding on each Anthropic FRT publication as it drops (their red.anthropic.com blog).
  • Attend one SF security event/month (BSides SF, DEF CON meetups, AI security meetups). Aim: two named contacts by week 12.
  • Only apply after Flagship 1 + one CVE. Cold apps without artifacts are ignored.
03What NOT to spend time on
  • Yet another safety-eval benchmark. You already have RedBench + Probe — extend, don't restart.
  • Long ML training runs. FRT is applied evaluation, not model training. Vlad's "below the stack" is the wrong track for this role.
  • Paid CTF platforms before you've cleared picoCTF's free set.
  • Cold outreach without a public artifact behind you. Wait until Flagship 1 ships.
  • Chasing 100% novelty. Porting a proven pattern (Cybench, XBOW) with your own twist is faster and more legible.

02Cyber-agent benchmarks (the frame everyone builds against)

04Vlad Feinberg's frame (adapted to FRT-Cyber)

Vlad's post is about "above vs. below the stack." For FRT-Cyber, you're above the stack: rigorous, controlled experiments on agent behavior in adversarial environments. His concrete rules still apply.

  • Screen-record yourself doing the work. Real solves, real terminals. Post on YouTube unlisted; link from writeups.
  • Ship end-to-end. One complete artifact beats three half-built ones.
  • Use AI aggressively — but only for what you already understand. Don't outsource the reasoning; outsource the typing.
  • Horizontal thinking. Don't just optimize obvious metrics (accuracy); measure cost, latency, tool-turn distribution, failure modes.
  • Consistent small bets. Bi-weekly writeup > monthly essay.
01Ship-in-90-days skills

Only what you need for the three flagships. No credentialism — everything below is measurable by GitHub + writeups.

Agent scaffolding (already strong)

  • Extend: tool-use loop with structured actions + observations + retries
  • Add: trajectory replay (record every action, deterministic re-run)
  • Add: cost + budget guardrails — you have this in RedBench
  • Study: Voyager, SWE-agent, Cline loop designs

Sandboxing

  • Docker + --network=none + --cap-drop=ALL baseline
  • gVisor for stronger isolation of untrusted binaries
  • Firecracker microVMs for kernel-exploitation targets
  • seccomp filters for tool-execution containers

Debugging & introspection

  • gdb / pwndbg / gef — muscle memory
  • Ghidra — REs at the level of a decent CTF pwn player
  • strace, ltrace, tcpdump — for observability during agent runs
  • Wireshark for the purple-arena demo

Web/API pentest tooling

  • Burp Suite Community — proxy, repeater, intruder basics
  • sqlmap, ffuf, httpx — automation glue
  • Nuclei templates — read some, then write one

Fuzzing

  • AFL++ on a real corpus (start with libpng)
  • Understand harness design well enough to write one for a new target
  • Coverage-guided vs. dumb fuzzing — trade-offs

Eval & measurement discipline

  • Seed control, deterministic replay, judge separation — you have these
  • Reproducibility standards (Docker images, pinned deps, published JSON)
  • Cost tracking per run (already in RedBench)
  • Human-baseline collection (this is what makes results interpretable)
02Deliberately deprioritized
  • CUDA / kernels / quantization. Wrong track for FRT-Cyber. Save for a different role.
  • ML training from scratch. You'll evaluate frontier models, not train them.
  • Front-end polish beyond Probe's level. Enough to demo; not enough to compete with product engineers.
  • Rust rewrites. Python fluency is the bar; Rust is nice-to-have and time-expensive.
01Open models to build with

Pick two open coders + one frontier API. Run every flagship experiment across all three so you have honest cross-model deltas to publish. Cost-wise: dev on Haiku or a local Qwen; final runs on Sonnet/Opus.

ModelWhyWhere it fits
Qwen 3 Coder 32B Currently the strongest open coder in this size class. Tool-use RL'd, long-context. Runs on one H100 or via Together/Fireworks. Primary open baseline in Flagship 1. Cheap iteration loop.
DeepSeek-V3.1 / R1 Reasoning-tuned; strong on multi-step problems. Cheap on DeepSeek's own API. Public weights. Second open baseline. Best "reasoning" comparison point.
Llama 3.3 70B Instruct The "boring default" for reproducibility papers — reviewers expect it. Include for third comparison in published tables.
WhiteRabbitNeo / Lily-Cybersecurity Cyber-fine-tuned open models. Weak overall but worth including as domain-specialist reference. Optional sidebar comparison.
Claude Haiku 4.5 Cheapest frontier tool-use loop. Fast enough for iterative agent dev. Dev-loop workhorse across all flagships.
Claude Sonnet 4.6 / Opus 4.7 Frontier baseline. Sonnet for volume runs; Opus for headline table. Final results in every writeup.
GPT-5 / GPT-4.1 Second frontier lab. Required for cross-lab honesty. Include in every published table.
02Serving stack
  • ollama for local dev on Qwen / DeepSeek — same as your current Probe replay setup.
  • vLLM when you need real throughput on rented A100/H100 (Lambda, RunPod).
  • Together or Fireworks for OpenAI-compatible endpoints on open weights — cleanest way to swap models in RedBench.
  • Keep PROBE_REPLAY=1-style fixture mode for offline determinism in tests.
03Frameworks worth adopting

Inspect (UK AISI)

The eval framework labs actually use. Adopting Inspect for your CTF-bench = instant credibility + easy to submit results to AISI's leaderboards.

SWE-agent / OpenHands

Open agent scaffolds with tool-use loops. Read the ACI (Agent-Computer Interface) design — best in the field.

Claude Code SDK

Anthropic's own agent harness. Building a cyber-agent on it is a strong tacit signal you can read their infra.

METR task-standard

The evaluation task specification standard. Package a picoCTF challenge in METR's format; publish it back.
